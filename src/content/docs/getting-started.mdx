## Install

From your local checkout of `anthurium-ai/orca`:

```bash
./install.sh
agent-orca --version
```

## Prepare an execution root

In the directory where you want blueprint state and evidence to live:

```bash
cp /path/to/orca/orca.yaml .
```

`orca.yaml` defines the deterministic validation contract for blueprint `check` nodes.

## Validate and run a blueprint

```bash
agent-orca blueprint lint blueprints/orca-pr-default-v1.yaml
agent-orca blueprint run blueprints/orca-pr-default-v1.yaml \
  --input change_request="tighten blueprint evidence output for failed runs"
agent-orca blueprint run blueprints/work-default-v1.yaml --profile strict
agent-orca blueprint evidence --newest
```

The default day-to-day blueprint in the Orca repo is `blueprints/orca-pr-default-v1.yaml`.

Blueprint runs persist state and emit evidence with explicit terminal decisions: `PASS`, `WARN`, or `BLOCK`.

## Shipped Orca blueprints

- `blueprints/orca-pr-default-v1.yaml`
  The main product/code workflow for Orca itself.
- `blueprints/orca-docs-refresh-v1.yaml`
  A docs and messaging workflow that accepts richer context such as `prd`, `acceptance_criteria`, and `constraints`.
- `blueprints/orca-release-readiness-v1.yaml`
  A release gate that validates the repo, lints the blueprint catalogue, builds the CLI, and pauses for approval.
- `blueprints/dogfood-orca-v1.yaml`
  A minimal self-hosting workflow kept as a direct example.
- `blueprints/work-default-v1.yaml`
  A small deterministic validation example.

## Pass richer context to a blueprint

Blueprints can declare hydration inputs and you pass them with repeated `--input key=value` flags.

For example, the docs workflow can take a PRD and explicit acceptance criteria:

```bash
agent-orca blueprint run blueprints/orca-docs-refresh-v1.yaml \
  --input change_request="refresh the docs for the new blueprint catalogue" \
  --input prd="Orca should present a small set of practical blueprints for product, docs, and release work." \
  --input acceptance_criteria="README and dogfood docs show the new default blueprint and when to use each one." \
  --input constraints="Do not describe removed queue or worker features."
```

Those inputs are rendered into `agent` and `approve` prompts automatically and are also exposed to command nodes through environment variables like `ORCA_BLUEPRINT_INPUT_PRD`.

## Evidence

Blueprint evidence is written under:

```text
.agent-orca/runs/blueprint/<blueprint-name>/<run-id>/blueprint-state.evidence.json
```

Use `agent-orca blueprint evidence` for blueprint-level decision and duration summaries.
