title: CLI reference
---

Orca ships as the `agent-orca` binary.

## Core

- `agent-orca blueprint init <file>` — generate a starter blueprint file
- `agent-orca blueprint lint <file>` — validate a blueprint file
- `agent-orca blueprint run <file> [--json] [--restart] [--profile default|safe|fast|strict] [--root dir] [--state path] [--input key=value]...` — run a blueprint workflow
- `agent-orca blueprint evidence [--json] [--newest] [--limit N] [--days N] [--root dir]` — summarize local blueprint evidence

## Utilities

- `agent-orca version` / `agent-orca --version` — build/version info

## Node contract

Blueprint node types:
- `cmd` and `ci` execute shell commands
- `check` runs the deterministic contract from `orca.yaml`
- `wait` sleeps for a duration
- `agent` and `approve` can either record prompts only or execute a command against a rendered prompt contract

When an `agent` or `approve` node includes both `prompt` and `run`, Orca exposes:
- `ORCA_BLUEPRINT_NODE_PROMPT`
- `ORCA_BLUEPRINT_NODE_PROMPT_FILE`
- `ORCA_BLUEPRINT_NODE_NAME`
- `ORCA_BLUEPRINT_NODE_TYPE`
- `ORCA_BLUEPRINT_RUN_ROOT`

Hydration inputs are also available to command nodes as env vars such as `ORCA_BLUEPRINT_INPUT_PRD`.
